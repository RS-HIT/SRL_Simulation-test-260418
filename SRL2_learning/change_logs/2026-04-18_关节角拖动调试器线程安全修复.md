# 2026-04-18 关节角拖动调试器线程安全修复

## 问题现象

运行 [debug_joint_angle_tuner.py](/e:/project/codetest/SRL2_learning/scripts/debug_joint_angle_tuner.py) 一段时间后，终端报错：

```text
ERROR: mj_copyDataVisual: attempting to copy mjData while stack is in use
```

随后 viewer 关闭。

## 根因

问题不是关节限位，也不是 viewer 本身，而是线程并发访问 MuJoCo 数据：

- Tk UI 线程在 [debug_joint_angle_tuner.py](/e:/project/codetest/SRL2_learning/scripts/debug_joint_angle_tuner.py) 的 `_refresh_ui_labels(...)` 里调用了 [compute_forward_kinematics(...)](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py)
- viewer 线程同时也在调用 [compute_forward_kinematics(...)](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py)
- 而 [compute_forward_kinematics(...)](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py) 会写入并读取同一个 `model_context.data`

MuJoCo 的 `mjData` 不是线程安全对象。两个线程同时碰同一个 `mjData`，就会触发这类错误。

## 修复方式

修改文件：

- [debug_joint_angle_tuner.py](/e:/project/codetest/SRL2_learning/scripts/debug_joint_angle_tuner.py)

修复原则：

- 只有 viewer 线程允许访问 MuJoCo 的 `model` / `data`
- Tk UI 线程不再直接调用正运动学
- UI 线程只读取 viewer 线程更新好的缓存字符串

具体改动：

1. 新增缓存字段：
   - `latest_flange_position_text`
   - `latest_tool_position_text`
2. UI 线程的 `_refresh_ui_labels(...)` 不再调用 MuJoCo
3. viewer 线程在每次算完 FK 后，把 `flange/tool` 结果写入缓存

## 结果

这次修复后：

- `mj_copyDataVisual: attempting to copy mjData while stack is in use` 的根因已经被移除
- 调试器不会再因为 Tk 线程和 viewer 线程并发访问 `mjData` 而闪退
