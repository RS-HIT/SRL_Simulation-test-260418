# 14_末端坐标驱动实验说明

## 这个实验到底在做什么

这个实验的输入不是“每个关节转多少角度”，而是：

- 一个世界坐标系下的目标点 `(x, y, z)`

程序会按下面这条链路工作：

1. 加载当前 MuJoCo 模型
2. 明确四个坐标系的定义
3. 用教学版数值逆运动学求一组目标关节角
4. 生成关节轨迹
5. 用 MuJoCo 回放
6. 记录目标点、法兰点、工具点和误差

## 四个坐标系必须分清

### 1. world frame

世界坐标系。

大白话：
整个仿真场景的“总地图”。

### 2. base frame

基座坐标系。

大白话：
机械臂底座装在世界里的位置和朝向。

当前来源：
- 运行时 URDF 中的 `world_to_base`

对应常量位置：
- [urdf_real_mesh_demo_config.json](/e:/project/codetest/SRL2_learning/configs/urdf_real_mesh_demo_config.json)

关键字段：
- `base_position`
- `base_euler`

### 3. flange frame

末端法兰坐标系。

大白话：
机械臂本体最后一级参考点。

当前默认参考：
- `Link3 body`

如果配置里给了有效 `site`，则会优先使用该 `site`。

### 4. tool frame

工具坐标系。

大白话：
真正拿来做任务、也真正拿来比较误差的点。

当前定义：

`tool frame = flange frame + 工具偏移`

对应常量位置：
- [tool_frame_config.json](/e:/project/codetest/SRL2_learning/configs/tool_frame_config.json)

关键字段：
- `tool_translation_xyz`
- `tool_rotation_rpy`

兼容字段：
- `translation_xyz`
- `rotation_rpy`

## 当前误差到底基于谁

当前真正参与误差比较的是：

- `tool frame` 原点

不是：
- 单纯的 `Link3 body` 原点
- mesh 外观上你肉眼觉得像“末端”的那个位置

所以判断误差是否可信，必须同时看：
- 法兰点在哪里
- 工具点在哪里
- viewer 里画出来的坐标轴是不是和 CSV 导出的点一致

## viewer 现在默认显示什么

默认运行：

```powershell
python SRL2_learning/scripts/run_cartesian_target_experiment.py
```

viewer 会默认打开，并显示四组坐标系：
- world frame
- base frame
- flange frame
- tool frame

颜色固定：
- X 红
- Y 绿
- Z 蓝

关闭 viewer：

```powershell
python SRL2_learning/scripts/run_cartesian_target_experiment.py --no-viewer
```

## 结构检查脚本

如果你怀疑“误差很小”不可信，先跑：

```powershell
python SRL2_learning/scripts/inspect_end_effector_frames.py
```

它会打印：
- 当前场景模型路径
- 全部 joint 名称
- 全部 body 名称
- 全部 site 名称
- 当前法兰参考来自哪个 body/site
- 当前 world/base/flange/tool 四个坐标系的位置
- 当前工具偏移配置是多少
- 当前真正参与误差比较的是哪个点

## 当前 CSV 里重点看哪些字段

当前主字段是：
- `base_x/base_y/base_z`
- `flange_x/flange_y/flange_z`
- `tool_x/tool_y/tool_z`
- `target_x/target_y/target_z`
- `tool_error_x/tool_error_y/tool_error_z`
- `tool_error_norm`

兼容说明：
- 旧版本曾大量使用 `tcp_*`
- 现在推荐你把 `tool_*` 作为主字段理解
- 在项目语义里，当前 `TCP = tool frame`

## 当前结果里哪些是严格读取，哪些是近似

### 严格来自 MuJoCo 位姿读取

- flange 世界坐标
- tool 世界坐标
- viewer 里显示的四组坐标系原点与方向

### 教学版近似

- 逆运动学是教学版数值法
- 当前没有专用工业 TCP site
- 当前默认法兰参考仍然只是 `Link3 body`
- 当前主要做位置目标，不做工业级姿态目标

## 如果你觉得结果不合理，优先检查什么

1. `inspect_end_effector_frames.py` 里当前法兰参考到底是谁
2. `tool_frame_config.json` 里的工具偏移是不是写成了错误单位或错误方向
3. viewer 里 `tool frame` 是否真的相对 `flange frame` 发生了偏移
4. CSV 里的 `tool_*` 和 `flange_*` 是否符合你的预期
5. 当前目标点是不是恰好靠近法兰原点，导致你误以为工具点也对了
