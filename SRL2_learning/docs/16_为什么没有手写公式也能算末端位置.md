# 16_为什么没有手写公式也能算末端位置

## 先说结论

当前 `SRL2_learning` 里计算末端点位置，不是靠我手写一套“各连杆几何关系公式”。

当前做法是：

1. 先把机械臂的结构信息交给 MuJoCo 模型
2. 把关节角写进 MuJoCo 的 `qpos`
3. 调用 MuJoCo 的前向运动学计算
4. 直接从 MuJoCo 读取指定 `body` 或 `site` 的世界坐标
5. 如果启用了工具偏移，再在这个结果上叠加工具坐标系偏移

也就是说：

**几何关系公式没有消失，它们只是被“放进了模型和物理引擎里”，而不是手写在 Python 源码里。**

---

## 1. 模型几何关系到底藏在哪里

机械臂每个连杆和关节的空间关系，主要来自模型文件，而不是来自单独一页公式。

当前实验实际加载的模型入口在：

- [model_context.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/model_context.py)

这个文件里的 `load_real_mesh_model_context(...)` 会做这些事：

1. 读取真实网格实验配置  
   对应配置文件：
   - [urdf_real_mesh_demo_config.json](/e:/project/codetest/SRL2_learning/configs/urdf_real_mesh_demo_config.json)

2. 准备运行时 URDF / MJCF  
   对应适配器：
   - [urdf_real_mesh_mujoco.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/adapters/urdf_real_mesh_mujoco.py)

3. 加载运行时场景模型  
   最终得到：
   - `model`
   - `data`

这里的 `model` 里已经包含了：
- 关节顺序
- 关节轴方向
- 连杆层级关系
- 每个 body 相对父节点的位姿
- world 到 base 的固定变换

所以，从数学意义上讲，机械臂的空间几何关系已经被编码进 MuJoCo 模型里了。

## 2. 末端位置是怎么真正算出来的

真正的正运动学入口在：

- [forward_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py)

关键函数是：

- `compute_forward_kinematics(...)`

这个函数做的事情可以用一句话概括：

**先让 MuJoCo 根据当前关节角把整台机械臂的姿态算一遍，再去读末端参考点的世界坐标。**

### 2.1 第一步：把关节角写进模型

这一层发生在：

- [model_context.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/model_context.py)

函数：

- `MujocoKinematicModelContext.set_joint_positions(...)`

它会把输入关节角写入：

```python
self.data.qpos[qpos_index] = float(joint_value)
```

然后调用：

```python
mujoco.mj_forward(self.model, self.data)
```

这一步非常关键。

`mj_forward(...)` 的作用就是：
- 根据当前关节角
- 沿着模型树
- 计算每个 body/site 的当前世界位姿

所以，你虽然没有看到我手写“第 1 杆乘第 2 杆乘第 3 杆”的矩阵公式，但 MuJoCo 已经帮你做了这件事。

### 2.2 第二步：读取末端参考点位置

在 [forward_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py) 里，函数：

- `_read_flange_pose(...)`

会优先尝试读取 `site`，如果没有有效 `site`，就回退读取 `body`。

当前默认法兰参考是：

- `Link3 body`

对应读取逻辑：

```python
body_id = mujoco.mj_name2id(context.model, mujoco.mjtObj.mjOBJ_BODY, context.reference_body_name)
position = np.array(context.data.xpos[body_id], dtype=float)
rotation = np.array(context.data.xmat[body_id], dtype=float).reshape(3, 3)
```

这里的含义是：

- `xpos[body_id]`：这个 body 在世界坐标系下的位置
- `xmat[body_id]`：这个 body 在世界坐标系下的旋转矩阵

所以法兰点位置并不是“猜”的，而是 MuJoCo 当前状态直接算出来再读出来的。

## 3. 工具点为什么还能再往前偏一点

当前项目不只算法兰点，还支持工具点。

工具偏移定义在：

- [tool_frame.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/tool_frame.py)

对应配置文件：

- [tool_frame_config.json](/e:/project/codetest/SRL2_learning/configs/tool_frame_config.json)

关键字段：

- `tool_translation_xyz`
- `tool_rotation_rpy`

在 [forward_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py) 里，工具点计算逻辑是：

```python
tool_offset_world = flange_rotation @ tool_frame.translation_vector
tool_position = flange_position + tool_offset_world
tool_rotation = flange_rotation @ tool_frame.rotation_matrix
```

它的数学意思是：

1. 先拿到法兰坐标系在世界里的姿态 `R_flange`
2. 把“工具相对法兰的局部偏移”旋转到世界坐标系
3. 再加到法兰位置上

这就是：

```text
p_tool = p_flange + R_flange * t_tool
```

所以工具点位置不是单独从模型里直接读出来的，而是：

- 法兰点世界位姿
- 加上工具偏移

共同决定的。

## 4. 那逆运动学为什么也能做

逆运动学入口在：

- [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py)

关键类和函数：

- `DampedLeastSquaresIKSolver`
- `solve_inverse_kinematics(...)`

这里的思路是：

1. 给一组当前关节角
2. 用正运动学算出当前工具点位置
3. 和目标点做差
4. 用雅可比矩阵估计“关节该怎么改”
5. 一步一步迭代逼近目标

### 4.1 误差从哪里来

在 [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py) 里：

```python
current_position = np.array(fk_result.tcp_position, dtype=float)
error_vector = target - current_position
```

当前这里虽然还兼容用了 `tcp_position` 这个旧名字，但它在当前项目语义里等价于：

- `tool_position`

也就是说，逆运动学真正追的是工具点。

### 4.2 雅可比为什么不需要手写

这里也没有手写解析 Jacobian 公式。

而是采用了有限差分近似，在：

- [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py)

函数：

- `_compute_position_jacobian(...)`

做法是：

1. 先记录当前工具点位置
2. 每次只微小扰动一个关节
3. 再重新调用正运动学
4. 看工具点位置怎么变
5. 用“位置变化 / 关节微小变化”近似这一列雅可比

即：

```text
J[:, i] ≈ (p(q + dq_i) - p(q)) / dq
```

这样就不需要你手工写出复杂的解析式。

代价是：
- 速度比解析雅可比慢一些
- 但教学版更直观，也更稳妥

## 6. 为什么这套方法成立

因为这里的“公式”其实分成两层：

### 第一层：几何关系公式

它们在模型里。

也就是：
- URDF / MJCF 里定义的连杆层级、关节轴、固定变换

这些内容由：

- [urdf_real_mesh_mujoco.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/adapters/urdf_real_mesh_mujoco.py)
- [model_context.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/model_context.py)

组织并加载给 MuJoCo。

### 第二层：数值求解公式

它们在代码里。

例如：
- `p_tool = p_flange + R_flange * t_tool`
- 有限差分 Jacobian
- Damped Least Squares 更新步

这些在：

- [forward_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/forward_kinematics.py)
- [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py)

里体现。

所以，不是“没有公式”，而是：

**结构公式交给模型，数值求解公式写在代码里。**

## 7. 当前方法的边界

这套实现是教学版，不是假装工业级精确求解。

当前边界是：

1. 当前默认法兰参考还是 `Link3 body`  
   对应文件：
   - [cartesian_target_experiment.json](/e:/project/codetest/SRL2_learning/configs/cartesian_target_experiment.json)

2. 当前没有专用工业 TCP site  
   所以工具点是“法兰点 + 工具偏移”

3. 逆运动学用的是数值法，不是解析解  
   对应文件：
   - [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py)

4. 当前主要做位置误差，不做工业级姿态误差优化  
   对应文件：
   - [inverse_kinematics.py](/e:/project/codetest/SRL2_learning/src/srl2_learning/kinematics/inverse_kinematics.py)
