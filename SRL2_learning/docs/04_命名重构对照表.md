# 04 命名重构对照表

当前表格只记录“已经迁移到学习版”的命名重构项。

| 原变量 / 函数 / 类名 | 新名称 | 修改原因 | 是否影响外部调用 |
| --- | --- | --- | --- |
| `jointToMotor` | `joint_to_motor_commands` | 改成见名知意的函数名，明确输入输出是“命令”而不是单个值 | 是 |
| `motorToJoint` | `motor_to_joint_state` | 明确这是“状态回算”，不是一般意义上的任意转换 | 是 |
| `MOTION_CMD` | `DesiredMotionState` | 更容易让新手理解“这是期望状态容器” | 是 |
| `MOTION_STATUS` | `MotionObservationState` | 强调这是“观测到的状态” | 是 |
| `Diff_va` | `DifferentiatedSignalState` | 原名缩写过多，新名直接表达“差分后的信号状态” | 是 |
| `FITER_STATUS` | `LowPassFilterState` | 修正拼写问题，并明确其用途 | 是 |
| `Filter` | `LowPassFilter.update` | 明确这是一阶低通滤波器更新动作 | 是 |
| `motionplanning` | `LinearInterpolationTrajectoryPlanner` | 说明教学版当前采用的具体规划方式 | 是 |
| `dynamics` | `OfflineDynamicsService` | 明确这是离线教学接口，不是原版实时数值模块 | 是 |
| `m_TStep` | `control_period` | 新手更容易理解这是“控制周期” | 是 |
| `m_Desire` | `desired_state` / `desired_motion_state` | 原名不完整，新名更准确 | 是 |
| `m_RMLMotion` | `joint_trajectory_runtime` 的概念拆分到规划器与控制器 | 降低一个结构体承载过多责任的问题 | 是 |
| `sendMotorCmds` | `MockActuatorRecorder.record` | 当前阶段用记录命令替代真实下发，更符合离线教学目标 | 是 |
